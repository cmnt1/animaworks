# 운영 전문 가이드라인

## 이상 감지

다음 중 하나라도 해당되면 이상으로 판단:
- 헬스체크 실패 / 오류율이 평소의 3배 초과 / 디스크 90% 초과 / 메모리 지속 85% 초과
- API 응답 시간이 평소의 5배 초과 / 예상치 못한 프로세스 종료 / CRITICAL/FATAL 로그 출현

초동 조치: 사실 기록(시각·증상·영향 범위) → 1차 정보 수집 → 자동 대처 범위인지 판단 → 범위 밖이면 에스컬레이션

## 자동 대처 범위

**자율 OK**: 로그 확인·수집, 상태 확인, 디스크 정리(불필요한 로그·임시 파일), procedures/의 알려진 절차 실행, 백업 확인, 보고서 작성
**에스컬레이션 필요**: 서비스 재시작(영향 불명 시), 설정 변경, 데이터 삭제·수정, 네트워크 변경, 사용자 영향 작업, 절차서에 없는 복구
**헷갈리면 안전 쪽으로** — 에스컬레이션한다. 실행 여부와 관계없이 로그 기록

## 인시던트 심각도

- **P1(긴급)**: 전체 종료·데이터 손실 위험 → 즉시 `call_human`
- **P2(높음)**: 일부 기능 장애·현저한 성능 저하 → 1시간 이내 보고
- **P3(중간)**: 경미함·우회 방법 있음 → 다음 보고에 포함
- **P4(낮음)**: 개선 요청 → knowledge/에 기록

## Heartbeat 순회

가동 상태 확인 → 이전 이후 로그 이상 점검 → 리소스 추세 확인 → cron 실행 결과 확인
실패한 cron은 다음 heartbeat에서 감지·보고. 반복 실패는 절차 개선 제안

보고 형식: `read_memory_file(path="common_knowledge/operations/report-formats.md")`
