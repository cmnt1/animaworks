# 사용 사례: 지식 관리 및 문서 정비

절차서 작성·업데이트, FAQ 정비, 정보 구조화 등 조직의 지식을 관리하고 발전시키는 사용 사례입니다.

---

## 이런 문제를 해결할 수 있습니다

- 절차서가 오래된 채로 업데이트되지 않음
- 같은 질문에 여러 번 답변하고 있음
- 특정인에게만 있는 지식이 공유되지 않음
- 문서가 여기저기 흩어져 있어 찾기 어려움
- 신입 인수인계에 시간이 오래 걸림

---

## 패턴 1: 절차서 자동 작성 및 업데이트

### 수행 작업
실제 작업 로그에서 절차서를 자동 생성하고, 변경 사항이 있으면 업데이트합니다.

### 동작 흐름
1. 작업 실행 로그를 모니터링
2. 반복적으로 수행되는 작업 패턴을 감지
3. 절차서 초안을 자동 생성:
   - 사전 조건
   - 절차(단계별)
   - 주의 사항 및 자주 발생하는 오류
   - 완료 조건
4. 인간의 검토 후 정식 버전으로 저장

### 활용 예시
- 서버 배포 절차를 실행 로그에서 자동 생성
- 트러블슈팅 대응 이력에서 FAQ로 정리
- 새 도구의 설정 절차를 첫 작업 시 기록

### 핵심 포인트
- "같은 패턴이 3번 나오면 절차서로 작성"이 적절한 기준
- 절차서에는 "왜 이렇게 하는지"에 대한 배경 설명도 포함
- 런타임에 문제가 발생하면 피드백으로 절차서에 반영

---

## 패턴 2: FAQ 구축 및 자동 응답

### 수행 작업
자주 묻는 질문과 답변을 데이터베이스화하고, 같은 질문이 오면 자동으로 응답합니다.

### 동작 흐름
1. 문의 이력을 분석
2. 자주 나오는 질문 패턴을 식별
3. 응답 템플릿을 작성
4. 새 문의가 들어오면:
   - FAQ에 해당하는 질문이 있으면 자동 응답
   - 없으면 인간에게 에스컬레이션
   - 인간이 응답하면 해당 Q&A를 FAQ에 추가

### 활용 예시
- "비밀번호 재설정 방법은?" → FAQ에서 자동 응답
- "○○ 기능 사용법은?" → 관련 절차서 링크를 제시
- 새 질문이 들어옴 → 인간의 답변을 기록하여 FAQ에 추가

---

## 패턴 3: 지식의 구조화 및 분류

### 수행 작업
흩어져 있는 정보를 체계적으로 정리하고, 검색하기 쉬운 형태로 정리합니다.

### 동작 흐름
1. 기존 문서·메모·채팅 로그를 수집
2. 내용을 카테고리별로 분류
3. 중복이나 모순을 감지
4. 구조화된 목차(인덱스)를 작성
5. 정기적으로 목차를 업데이트

### 활용 예시
- 프로젝트 설계 문서를 주제별로 정리
- 채팅에서 공유된 지식을 카테고리별로 정리
- 여러 파일에 흩어진 정보를 통합하여 하나의 가이드로 작성

---

## 패턴 4: 교훈 및 회고 축적

### 수행 작업
문제 발생 시 원인과 대책을 "교훈"으로 기록하고, 같은 문제의 재발을 방지합니다.

### 동작 흐름
1. 문제·장애 발생
2. 대응이 완료된 후 다음을 기록:
   - 무엇이 발생했는가(현상)
   - 왜 발생했는가(근본 원인)
   - 어떻게 대응했는가(대응 절차)
   - 앞으로 어떻게 예방할 것인가(재발 방지 대책)
3. 유사한 문제가 발생하면 과거의 교훈을 자동 검색하여 제시

### 활용 예시
- "이전에도 유사한 오류가 발생했습니다. 지난번 대처 방법: ○○"
- 장애 대응 후 "포스트모템 보고서"를 자동 생성
- 분기별로 "자주 발생하는 문제와 대책 목록"을 업데이트

---

## 패턴 5: 온보딩 자료 정비

### 수행 작업
새 멤버(인간 또는 Anima)가 조직에 합류할 때의 인수인계 자료를 정비하고 업데이트합니다.

### 동작 흐름
1. 기존 절차서·FAQ·규칙을 점검
2. 새 멤버에게 필요한 정보를 우선순위 순으로 정리
3. "먼저 읽어야 할 문서" 목록을 작성
4. 내용이 오래되지 않았는지 정기적으로 확인

### 활용 예시
- "새 엔지니어가 입사하면 이 5개 문서를 전달" 목록
- 개발 환경 설정 절차를 최신 상태로 유지
- 조직의 규칙·관행을 정리한 "하우스 룰" 정비

---

## 패턴 6: 문서 신선도 관리

### 수행 작업
기존 문서의 내용이 현재 상황과 괴리되지 않았는지 정기적으로 확인합니다.

### 동작 흐름
1. 전체 문서의 최종 업데이트 날짜를 관리
2. 업데이트 후 일정 기간(예: 3개월)이 지난 문서를 목록화
3. 내용과 현재 상황을 비교하여 업데이트 필요 여부를 판단
4. 업데이트가 필요한 문서는 담당자에게 알림

### 활용 예시
- "다음 3개 절차서가 3개월 이상 업데이트되지 않았습니다"
- "절차서 A에 기재된 명령어가 버전 업그레이드로 변경되었습니다"
- "FAQ의 답변 B가 현재 UI와 일치하지 않습니다"

## 구성 힌트

### 최소 구성(Anima 1개)
- 1개가 지식 관리 전반을 담당
- 주로 인간의 지침에 따라 절차서를 작성·업데이트
- FAQ 자동 응답도 겸임

### 권장 구성
- **지식 관리 담당**: 문서 작성·업데이트·신선도 관리
- 다른 Anima(개발, 모니터링 등)가 발견한 지식을 지식 관리 담당에게 전달
- 지식 관리 담당이 체계적으로 정리·보존

### 효과적인 운영 팁
- 처음부터 완벽을 목표로 하지 않기. 문제가 발생하면 기록하는 것을 반복하며 키워나가기
- "검색해서 찾을 수 있음"이 가장 중요. 제목과 카테고리를 꼼꼼하게 붙이기
- 절차서는 "실행해서 동작하는 것"을 확인한 후 공개하기
- 정기적인 점검으로 낡은 정보를 업데이트·삭제하기
