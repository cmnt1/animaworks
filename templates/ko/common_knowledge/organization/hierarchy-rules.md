# 계층 간 규칙

AnimaWorks에서 Anima 간 커뮤니케이션에는 조직 계층에 기반한 규칙이 있다.
본 문서에서는 각 관계(상급자·부하·동료·타 부서)에서의 규칙을 정의한다.

## 기본 원칙

- 조직 내 모든 소통은 `send_message`(메시징)으로 수행한다
- 내부 상태의 직접 공유는 금지. 자신의 언어로 압축·해석하여 전달한다
- 각 메시지에는 목적을 명확히 한다. 「무엇을 해주길 바라는지」「무엇을 전하고 싶은지」를 MUST 포함한다

## 상급자와의 커뮤니케이션(보고·연락·상담)

상급자는 `supervisor` 필드에서 지정된 Anima.
시스템 프롬프트의 「상급자」란에 표시된다.

### MUST(의무)

- 작업 완료 시 결과를 MUST 보고한다
- 작업 중 문제나 블로커가 발생한 경우 신속히 MUST 보고한다
- 자신의 판단 범위를 넘는 결정이 필요한 경우 MUST 상담한다
- 상급자의 지침에 대해 이해가 불명확한 경우 MUST 확인한다

### SHOULD(권장)

- 장기 작업의 경우 중간 진행 상황을 SHOULD 보고한다
- 문제 보고 시 「무슨 일이 있었는지」「시도한 것」「제안」을 세트로 SHOULD 전달한다
- 보고는 간결하게. 상세가 필요한 경우 파일에 작성해 참조를 SHOULD 보낸다

### 메시지 예

작업 완료 보고:
```
bob宛: APIエンドポイントの実装が完了しました。
- GET /api/users — ユーザー一覧取得
- POST /api/users — ユーザー新規作成
- テストも全件パス済みです。
次のタスクがあればご指示ください。
```

문제 보고:
```
bob宛: DB接続でタイムアウトが頻発しています。
- 発生: 本日14:00頃から
- 試したこと: コネクションプールのサイズ拡大（改善せず）
- 推測: 同時接続数が上限に達している可能性
- 提案: コネクションプールの最大値を50→100に変更してよいか確認したいです。
```

판단 상담:
```
alice宛: キャッシュ戦略について判断をお願いしたいです。
- 選択肢A: Redis導入（高速だがインフラコスト増）
- 選択肢B: ファイルキャッシュ（低コストだが速度に限界）
- 私の推奨はAですが、コスト面の判断はお任せします。
```

## 슈퍼바이저 도구

부하를 둔 Anima에는 조직 관리를 위한 전용 도구가 자동으로 활성화된다.

### ツール一覧

| ツール | 対象範囲 | 概要 | 主なパラメータ |
|--------|---------|------|----------------|
| `org_dashboard` | 全配下（再帰） | 配下全体のプロセス状態・最終アクティビティ・現在タスク・タスク数をツリー表示 | なし |
| `ping_subordinate` | 全配下（再帰） | 配下の生存確認。`name` 省略で全員一括、指定で単一 Anima のみ | `name`（任意） |
| `read_subordinate_state` | 全配下（再帰） | 配下の `state/current_state.md` を読み取り | `name`（必須） |
| `delegate_task` | 直属部下のみ | 完全な実行入力と追跡参照を原子的に登録し、部下へ通知 | `name`, `instruction`（必須）, `summary`, `acceptance_criteria`, `workspace`, `model`（任意） |
| `task_tracker` | 自分の委譲タスク | `delegate_task` で委譲したタスクの進捗を配下側キューから追跡 | `status`（任意: "all"/"active"/"completed", デフォルト "active"） |
| `audit_subordinate` | 全配下（再帰） | 活動タイムラインまたは統計サマリーを生成。`name` 省略で全配下を一括監査（統合タイムライン） | `name`（任意）, `mode`（任意: `"report"`/`"summary"`, デフォルト `"report"`）, `hours`（任意: 1〜168, デフォルト 24）, `direct_only`（任意: boolean）, `since`（任意: `"HH:MM"` 当日の開始時刻、指定時はhoursより優先） |
| `disable_subordinate` | 全配下（再帰） | 配下を休止（status.json enabled=false、約30秒でプロセス停止） | `name`（必須）, `reason`（任意） |
| `enable_subordinate` | 全配下（再帰） | 休止した配下を再開 | `name`（必須） |
| `set_subordinate_model` | 全配下（再帰） | 配下のモデルを変更（status.json 更新。反映には `restart_subordinate` が必要） | `name`, `model`（必須）, `reason`（任意） |
| `set_subordinate_background_model` | 全配下（再帰） | 配下のバックグラウンドモデル（Heartbeat/Cron用。Inboxはメイン）を変更。空文字でクリア。反映には `restart_subordinate` が必要 | `name`, `model`（必須）, `credential`, `reason`（任意） |
| `restart_subordinate` | 全配下（再帰） | 配下プロセスを再起動（restart_requested フラグ、約30秒で再起動） | `name`（必須）, `reason`（任意） |

`check_permissions` は全 Anima が利用可能（自分の権限一覧を確認）。

### 작업 위임 흐름

1. `delegate_task(name="dave", instruction="目的・成果物・制約・期限・必要な文脈", acceptance_criteria=["確認可能な完了条件"])`을 실행한다.
2. 완전한 입력과 추적 참조가 정규 작업 저장소에 원자적으로 등록된다.
3. 워커가 의존성과 여유 용량을 확인하고 실행 가능한 작업을 획득한다.
4. dave에게 DM으로 알림. DM은 실행 입력이 아니라 누락된 작업을 재생성하는 재료로 사용하지 않는다.
5. 자신의 위임 추적 항목은 동일한 작업에 대한 참조이며, 별도의 가변 복사본이 아니다.
6. `task_tracker(status="active")`로 진행 중인 위임 작업을 추적한다(`status="all"`로 전체, `status="completed"`로 완료된 것만)

### 하위의 상태 확인(정기적으로 수행해야 함)

```
org_dashboard()                        # 配下全体の状態をツリー表示
read_subordinate_state(name="dave")    # dave の現在タスクと保留タスクを確認
ping_subordinate()                     # 全員の生存確認
audit_subordinate(name="dave")         # dave の直近24時間の活動タイムライン
audit_subordinate(name="dave", mode="summary", hours=168)  # dave の直近7日間の統計サマリー
audit_subordinate()                    # 全配下の統合タイムライン（直近24時間）
audit_subordinate(direct_only=true)    # 直属部下のみの統合タイムライン
audit_subordinate(since="09:00")       # 全配下の今日9時以降の統合タイムライン
audit_subordinate(name="dave", since="13:00")  # dave の今日13時以降
```

#### audit_subordinate의 모드

| 모드 | 출력 내용 | 용도 |
|--------|---------|------|
| `report`(기본) | 시계열 타임라인. 이벤트별로 아이콘·시각·내용을 표시. 도구 사용은 하단에 집약 요약 | 「오늘 무엇을 했는지」 파악 |
| `summary` | 이벤트 수·작업 상태·통신 상대·오류 상세의 통계 표시 | 정량적 활동 평가 |

`name`를 생략하고 복수 Anima가 대상이 되는 경우, `report` 모드에서는 모든 Anima의 이벤트를 시계열로 병합한 **통합 타임라인**이 생성된다.

### 조직의 확장(신규 Anima 생성)

`skills/newstaff/SKILL.md`을 보유한 Anima는 `create_anima` 도구로 신규 Anima를 생성할 수 있다.
캐릭터 시트(`character_sheet_content` 또는 `character_sheet_path`)를 지정하고,
생성 후에는 config.json에 자동 등록되며 서버 재로드로 활성화된다.
`supervisor`를 생략한 경우, 호출한 Anima가 상급자로 설정된다.

## 부하와의 커뮤니케이션(지시·확인)

부하는 시스템 프롬프트의 「부하」란에 표시되는 Anima.
자신을 `supervisor`으로 설정한 모든 Anima가 해당한다.

### MUST(의무)

- 작업 지시 시 다음을 MUST 포함한다:
  - **목적**: 왜 이 작업이 필요한가
  - **기대하는 결과물**: 무엇을 만들 것인가·무엇을 할 것인가
  - **결과물 경로**: 위임 대상 자신의 디렉터리 또는 `common_knowledge/`(자신의 `knowledge/`은 지정 불가 — 부하는 쓸 수 없음)
  - **마감일·우선순위**: 언제까지, 어느 정도 급한가
- 부하의 완료 보고를 받으면 확인 결과를 MUST 피드백한다
- 정기적으로 `org_dashboard`로 하위의 상태를 MUST 확인한다

### SHOULD(권장)

- 부하의 speciality를 고려하여 작업을 SHOULD 배정한다
- 지시는 구체적으로. 모호한 표현(「좋게 해줘」)은 SHOULD 피한다
- 부하가 여러 명인 경우, 작업의 의존 관계를 SHOULD 정리한 후 지시한다

### MAY(임의)

- 부하의 성장을 위해 다소 도전적인 작업을 MAY 배정한다
- 부하 간 협력이 필요한 경우, 관계자를 명시하여 MAY 지시한다

### 메시지 예

작업 지시:
```
dave宛: ユーザー認証APIの実装をお願いします。
- 目的: フロントエンドからのログイン機能を実現するため
- 成果物: POST /api/auth/login エンドポイント（JWT返却）
- 仕様: メールアドレス+パスワードでの認証。失敗時は401を返す
- 期限: 今週金曜まで
- 関連: eve がフロントエンド側のログイン画面を並行で作成中です。
  API仕様の質問があれば eve と直接やりとりして構いません。
```

확인·피드백:
```
dave宛: 認証APIの実装、確認しました。
- ログイン・ログアウトとも正常動作を確認
- 1点: トークンの有効期限が設定されていないようです。24時間で期限切れにしてください
- それ以外は問題ありません。修正後に再度報告をお願いします。
```

## 동료와의 커뮤니케이션(협력·조정)

동료는 동일한 `supervisor`을 가진 Anima.
시스템 프롬프트의 「동료」란에 표시된다.

### SHOULD(권장)

- 관련 업무를 담당하는 동료와는 직접 소통을 SHOULD 수행한다
- 자신의 작업이 동료의 작업에 영향을 미치는 경우 사전에 SHOULD 공유한다
- 공동 작업 시, 누가 무엇을 담당할지 SHOULD 명확히 한다

### MAY(임의)

- 동료의 speciality에 관한 지식을 MAY 상담한다
- 리뷰나 의견을 MAY 요청한다

### 메시지 예

협력 요청:
```
eve宛: 認証APIの実装が完了したので共有します。
- エンドポイント: POST /api/auth/login
- リクエスト: { "email": "...", "password": "..." }
- レスポンス: { "token": "JWT文字列", "expires_in": 86400 }
- エラー時: 401 { "error": "Invalid credentials" }
フロントエンド側のログイン画面で使ってください。質問があればいつでもどうぞ。
```

상담:
```
carol宛: 管理画面のUIについて相談したいのですが、
ユーザー一覧画面のテーブルレイアウトについて、
20列以上のカラムがあるのですが、どう表示するのが良いでしょうか。
あなたのUXの観点からアドバイスいただけると助かります。
```

## 타 부서 멤버와의 커뮤니케이션

타 부서란 자신과 다른 `supervisor`을 가진 Anima.
동료란에 표시되지 않은 Anima가 해당한다.

### MUST(의무)

- 타 부서 멤버에게 직접 연락하는 것은 원칙적으로 MUST 하지 않는다
- 타 부서와의 협력이 필요한 경우, 자신의 상급자에게 그 사실을 MUST 전한다
- 상급자를 통해 상대 부서의 상급자에게 연락이 가고, 거기서 상대에게 지시가 내려간다

### 커뮤니케이션 경로

예: dave(bob 하위)가 frank(carol 하위)에게 연락하고 싶은 경우

```
正しい経路:
  dave → bob(自分の上司) → alice(共通の上司) → carol(frankの上司) → frank

間違い:
  dave → frank（直接連絡は禁止）
```

### 메시지 예

상급자에게의 요청(타 부서 협력이 필요한 경우):
```
bob宛: 顧客データのエクスポート機能について、
営業部の frank さんが必要とするCSVフォーマットの詳細を知りたいです。
carol さん経由で確認していただけますか？
```

### 왜 직접 연락을 피하는가

- 상급자가 업무의 전체 그림을 파악할 수 없게 된다
- 지시 체계가 혼란해져 모순된 지시가 나올 위험이 있다
- 각 부서의 상급자가 우선순위를 판단할 기회가 사라진다

## 최상위 Anima의 인간에게 연락

상급자(supervisor)가 설정되지 않은 최상위 Anima는 인간 관리자에게 직접 연락할 책임이 있다.
연락에는 `call_human` 도구를 사용한다.

### MUST(의무)

- 문제·오류·장애를 감지한 경우 `call_human`으로 MUST 연락한다
- 자신의 판단 범위를 넘는 결정이 필요한 경우 MUST 보고한다
- 부하로부터 에스컬레이션된 사항 중 자신이 해결할 수 없는 경우 MUST 보고한다

### SHOULD(권장)

- 중요한 작업 완료 시 SHOULD 보고한다
- 부하의 업무 상황에 우려가 있는 경우 SHOULD 보고한다

### MAY(임의)

- 정기 순회에서 특별한 문제가 없었던 경우 보고 MAY 하지 않는다
- 경미한 자동 복구가 완료된 경우 보고 MAY 하지 않는다

### 메시지 예

문제 보고:
```
call_human:
  subject: "本番環境のAPI応答遅延を検出"
  body: |
    14:00頃からAPIの応答時間が通常の3倍に増加しています。
    - 影響: ユーザー向けAPIの全エンドポイント
    - 試したこと: コネクションプールの状態確認（異常なし）
    - 推測: DBサーバーの負荷が高い可能性
    - 提案: DBサーバーのスケールアップを検討してください
  priority: high
```

판단 요청:
```
call_human:
  subject: "新機能リリースの承認依頼"
  body: |
    ユーザー認証機能の実装が完了し、全テストがパスしました。
    本番環境へのリリースについて承認をお願いします。
  priority: normal
```

## 긴급 시 예외 규칙

일반적인 계층 규칙에는 다음과 같은 예외가 있다.

### 긴급 상황의 정의

다음에 해당하는 경우 「긴급 상황」으로 예외 규칙을 MAY 적용한다:

- 시스템 장애나 서비스 중단이 발생하고 있다
- 보안 인시던트가 발생하고 있다
- 상급자가 장시간 응답하지 않는 상태가 계속되고 있다
- 마감일이 임박해 일반 경로로는 시간이 맞지 않는다

### 긴급 시 허용되는 행동

- 타 부서 멤버에게 직접 연락 MAY 한다(단, 사후에 상급자에게 MUST 보고)
- 상급자를 건너뛰어 그 위의 상급자에게 직접 연락 MAY 한다(단, 직속 상급자에게도 MUST 보고)
- 평소에는 상담이 필요한 판단을 스스로 내릴 MAY 있다(단, 사후에 MUST 보고·승인을 받는다)

### 긴급 연락의 메시지 예

```
frank宛: 【緊急】dave です。通常は上司経由ですが、緊急のためご連絡します。
本番環境でユーザーデータの不整合が発生しています。
営業側で顧客から問い合わせが来ていないか確認していただけますか？
bob と carol にも同時に報告しています。
```

상급자에게의 사후 보고:
```
bob宛: 【事後報告】本番障害の対応で、frank さん（carol配下）に直接連絡しました。
- 理由: 顧客データ不整合の影響範囲を緊急確認する必要があった
- 対応内容: frank さんに顧客からの問い合わせ状況を確認依頼
- 結果: 3件の問い合わせが来ており、frank さんが対応中
事後報告となり申し訳ありませんが、ご確認をお願いします。
```

## 규칙의 우선순위 요약

| 우선순위 | 규칙 | 분류 |
|--------|--------|------|
| 1 | 상급자에게의 문제 보고·에스컬레이션 | MUST |
| 2 | 작업 완료 보고 | MUST |
| 3 | 부하에게의 지시에 목적·결과물·마감일 포함 | MUST |
