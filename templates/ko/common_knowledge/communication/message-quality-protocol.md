# 메시지 품질 프로토콜

메시지 전송 전에 확인해야 하는 필수 항목.
상세 예시는 `communication/reporting-guide.md` / `communication/instruction-patterns.md` 참조.

---

## 1. 위임 지침의 필수 4항목

`delegate_task` 또는 요청 메시지에 반드시 포함할 것:

| # | 항목 | 내용 |
|---|------|------|
| 1 | 작업 내용 | 무엇을 할 것인가 (배경을 포함한 1-2줄 요약) |
| 2 | 완료 조건 | 무엇이 갖춰지면 완료인가 |
| 3 | 참조 정보 | 파일 경로 / Issue·PR URL / 관련 자료 |
| 4 | 마감일과 보고 대상 | 언제까지, 누구에게 보고할 것인가 |

**위임 전 체크**: 동일 Issue/PR에 미완료 위임이 없는지 `list_tasks`에서 확인할 것.

---

## 2. 완료 보고의 필수 3항목

완료 보고(intent="report")에 반드시 포함할 것:

| # | 항목 | 내용 |
|---|------|------|
| 1 | 결과 | 무엇이 완료되었는가 (1줄) |
| 2 | 산출물 | 파일 경로 / PR URL / 수치 결과 |
| 3 | 검증 근거 | 확인한 수단·건수·시각 |

**「이상 없음」이라도 필수**: 무엇을·몇 개를·언제 확인했는지 작성.

- 나쁜 예: 「전체 이상 없음」
- 좋은 예: 「Slack 3채널·Chatwork 2룸 확인, ERROR 0건, 최종 확인 14:52 JST」

---

## 3. 에스컬레이션의 필수 4항목

문제 보고·판단 요청에 반드시 포함할 것:

| # | 항목 | 내용 |
|---|------|------|
| 1 | 사실 | 무엇이 발생했는가 (시각+관측 사실만. 평가어·감정어를 넣지 않음) |
| 2 | 영향 | 누가/무엇이 중단되어 있는가 |
| 3 | 시도한 대책 | 자신이 시도한 것과 그 결과 |
| 4 | 선택지 | 2개 이상의 대응안과 추천안 |

**금지**: 사실 대신 평가어를 사용하는 것 (「심각한 상태」「전혀 안 되고 있음」 등).
사실과 시각을 먼저 쓰고, 평가가 필요하면 마지막에 한 문장으로 덧붙일 것.
