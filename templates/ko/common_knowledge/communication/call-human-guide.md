# call_human 가이드 — 인간에게 알림 보내기 및 답장 수신

## 개요

`call_human`은 인간 관리자에게 알림을 보내는 도구입니다. **일방통행이 아님** — 인간이 Slack 스레드에서 답장하면, 그 답장은 발신자 Anima의 Inbox로 자동 배송됩니다.

## 전송

```
call_human(
    subject="件名",
    body="本文（状況・試したこと・依頼内容を含める）",
    priority="normal"  # "normal" | "high" | "urgent"
)
```

| 파라미터 | 필수 | 설명 |
|-----------|------|------|
| `subject` | MUST | 제목 (간결하게) |
| `body` | MUST | 본문 (상황·시도한 것·요청 포함) |
| `priority` | MAY | `normal` (기본값), `high`, `urgent` |

### 언제 사용하는가

- 긴급도가 "높음"인 문제 (데이터 손실 위험, 보안, 서비스 중단)
- 자신의 판단 범위를 넘는 결정이 필요한 경우
- 최상위 Anima에서 상급자가 없는 경우의 에스컬레이션

자세한 판단 기준은 `troubleshooting/escalation-flowchart.md`을 참조.

### 제약

- `call_human`은 DM 속도 제한 (30/h, 100/day）의 **대상 외**
- 긴급 시에도 제한을 신경 쓰지 않고 전송할 수 있음

## 답장 수신

### 작동 방식

1. `call_human`으로 알림을 보내면 Slack에 메시지가 게시됨
2. 인간이 그 메시지의 **스레드 (thread)** 에서 답장함
3. 답장이 발신자 Anima의 Inbox로 자동 라우팅됨
4. 다음 Inbox 처리 주기 (보통 2초 이내에 감지)에서 답장이 처리됨

### 답장 메시지의 특징

수신한 답장 메시지는 다음 속성을 가짐:

- `source`: `"slack"` (Slack 경유 답장)
- `from_person`: `"slack:U..."` 형식 (Slack 사용자 ID)
- 일반 Inbox 메시지와 동일하게 처리됨

### 답장을 기다리는 경우

`call_human`을 보낸 후 답장을 기다려야 하는 경우:

1. 대기 상태를 `state/current_state.md`에 기록함
2. 답장은 다음 Inbox 처리에서 자동으로 도착함
3. 즉시 답장이 없어도, 인간이 답장한 시점에 자동 배송됨

### 답장에 응답하기

답장을 받으면 일반 Inbox 메시지와 동일하게 응답할 수 있음. 단, 답장 대상이 Slack 사용자이므로 `send_message`이 아니라, 채팅 응답 또는 추가적인 `call_human`로 대응함.

## 주의사항

- 답장 라우팅은 **Bot Token 모드** (`chat.postMessage`)로 전송된 알림만 지원. Webhook 모드에서는 답장이 도착하지 않음 (관리자 설정 문제이며, Anima 측에서 제어하는 것이 아님)
- 답장 매핑은 **7일간** 유지됨. 7일 이상 경과한 스레드에 대한 답장은 도착하지 않음
- 인간의 답장이 없어도, 필요에 따라 다시 `call_human`로 독촉할 수 있음
