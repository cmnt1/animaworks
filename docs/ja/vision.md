# Digital Anima の設計理念

**Organization-as-Code for LLM Agents**

AnimaWorks は、LLM エージェントを組織として定義し、仕事を委ね、継続的な協働を支えるシステムである。各 Digital Anima は固有の役割と記憶を持ち、メッセージを通して他者と連携する。

## 目指すもの

不完全な個の協働が、単一の全能者より堅牢な組織を作る。そして経験を記憶に積み重ねれば、それぞれの限界を越える判断につながる。

一つのモデルに全ての知識と仕事を集めるのではなく、個々の Anima が自分の専門性で判断し、必要なことを自分の言葉で共有する。組織を構成する個々の視野や能力の差は、役割を分けて協働するための設計要素である。

## 3 つの原則

### カプセル化された個

各 Anima は固有の記憶と状態を持つ。他者との連携はメッセージやタスクなど明示されたインターフェースを通じて行い、他者の内部状態を直接共有しない。この境界によって、役割と責任を分けられる。

### 経験を活かす記憶

Anima は会話履歴をそのまま全て読み込むのではなく、必要に応じて記憶を想起する。活動ログ、エピソード、知識、手順などの異なる情報を検索し、文脈に合わせて利用する。日次・週次の統合では候補や確認材料を用意し、内容の判断には Anima の処理も使う。記憶の構造と索引は[記憶システム](memory/index.md)を参照する。

### 組織としての協働

階層による監督と委任、共有チャネル、DM、タスク管理を組み合わせる。実行経路は[ライフサイクル](architecture/lifecycle.md)、プロセス分離は[プロセス構成](architecture/process.md)、連携方法は[メッセージング](architecture/messaging.md)を参照する。

## 適材適所のモデル選択

Anima ごとに異なるモデルと実行エンジンを選べる。現行の実行モードは Claude Agent SDK の `S`、Codex の `C`、Grok Build の `X`、Cursor Agent の `D`、Gemini CLI の `G`、LiteLLM を使う `A` である。モデル名からの自動解決に加え、Anima 単位で実行モードを設定できる。詳細と優先順位は[モデル実行](architecture/execution.md)と[設定リファレンス](reference/config.md)を参照する。

強力なモデルだけで組織を構成するのではなく、仕事の性質に応じて能力・応答時間・費用のバランスを取る。heartbeat や cron に別の背景モデルを設定することもできる。

## 設計の評価

この設計は、Anima が必要な経験を思い出し、結果から学び、適切な相手へ委任し、進捗や成果を共有できるかで評価する。記憶や自律性を掲げるだけでなく、日々の運用で判断と協働が改善することを目指す。

AnimaWorks は単独のチャットアシスタントではなく、複数の個が限界を持ちながらも組織として価値を生むための基盤である。
