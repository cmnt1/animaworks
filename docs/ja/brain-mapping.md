# 脳科学との対応

## 背景

AnimaWorks は、精神科臨床で観察される記憶・注意・実行機能の違いと、ソフトウェア工学のモジュール分離を設計の手がかりとする。脳をそのまま模倣するのではなく、情報処理の役割を分けるための設計対応として神経科学の知見を参照する。

## 全体マッピング

| AnimaWorks の概念 | 脳科学・認知科学上の対応 | 対応の要点 |
|---|---|---|
| LLM による推論と言語処理 | 大脳新皮質、とくに前頭前野の実行機能 | 想起された情報を使って判断し、応答を構成する。 |
| LLM の事前学習知識 | 大脳皮質に形成された一般的な知識パターン | 個別の経験から蓄積するファイルベース記憶とは別系統である。 |
| コンテキスト | ワーキングメモリ | 現在の注意の対象を一時的に保持する。詳細は[記憶システム](memory/index.md)を参照する。 |
| エピソード・知識・手順 | 海馬系・大脳皮質・基底核などの記憶機能 | 出来事、意味、手続きという異なる役割を分けて保持する。 |
| 自動想起と明示検索 | 手がかりによる想起と前頭前野の探索 | 文脈からの自動的な想起と、必要時に行う意図的な検索を併用する。 |
| heartbeat と定時実行 | 覚醒維持と概日リズム | 周期的な起動と時刻指定の実行を、個々の判断とは別の基盤として扱う。 |
| 複数 Anima の協働 | 分散認知・社会的認知 | 個々の内部状態を共有メモリに集約せず、通信と役割分担で協働する。 |

## 自動想起と選択的注意

自動想起は、手がかりに応じて関連する記憶をコンテキストに差し出す仕組みであり、脳の連想的な再活性化になぞらえられる。実装は `compact` を既定とし、現在の実行に必要な情報に絞る。チャネルや検索条件の詳細は[自動想起](memory/priming.md)を参照する。

## 設計原則の神経科学的根拠

### コンテキストの制限

ワーキングメモリには容量の制約がある（Cowan, 2001）。限られたコンテキストは単なる欠点ではなく、注意を関連情報へ向ける設計条件となる。AnimaWorks は必要な手がかりを想起し、長期記憶の全量を毎回提示しない。

### 統合と忘却

睡眠中の記憶統合やシナプス・ホメオスタシスの研究（Tononi & Cirelli, 2003）は、保持と選択の両方が記憶機能に関わることを示す。AnimaWorks でも記録を長期保管するだけでなく、利用状況や内容を見直す機会を設ける。現行の処理は[記憶の統合と忘却](memory/consolidation.md)を参照する。

### 不完全な個の協働

各 Anima の知識と視点を限定し、メッセージで情報を持ち寄る設計は、分散認知（Hutchins, 1995）や認知負荷の考え方（Sweller, 1988）と整合する。単一の主体へすべての情報や判断を集約するのではなく、役割を持つ個々の協働でシステム全体を構成する。

## 読み方

ここでの対応は設計を説明するためのマッピングであり、ソフトウェア機能と脳領域が生物学的に同一であることを主張するものではない。実装上の記憶構造は[記憶システム](memory/index.md)、実行モードは[実行モード](architecture/execution.md)を参照する。
